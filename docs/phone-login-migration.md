# 手机号主账号迁移

## 本次范围

第一阶段：阿里云短信验证码登录、自助绑定、迁移提醒。现有账户 ID 不变，余额、账单和 API Key 不迁移、不合并。用户直接短信验证后完成绑定，不需要管理员审核。

第二阶段已提供默认关闭的独立微信直登实现，待用户准备自己的认证服务号及网页授权权限后联调，见 [服务号微信直登](wechat-direct-login.md)。微信作为手机号主账号的另一种凭证；新微信先验证手机号，再绑定到该手机号所属账号，不按昵称或器灵数字 ID 合并。配置可用时界面默认微信登录，保留短信登录。

第三阶段：确认存量用户和管理员已绑定手机并告知截止时间后，关闭器灵登录。不能直接删除历史关联或根据微信昵称重建用户。

## 第一阶段行为

- 登录页提供原入口和手机验证码入口。已登录但未绑定者看到绑定提醒，可在个人中心自助绑定。
- 手机号使用中国大陆 11 位格式。其他地区不隐式归一化，以免产生重复身份。
- 一个账号只绑定一个手机号，一个手机号只归一个账号，数据库唯一约束兜底。不允许覆盖或自动合并。
- 绑定成功即撤销该账号的全部浏览器登录会话，用户重新使用手机验证码登录。此账号不再接受器灵登录；原 API Key 保留。
- 开启 `PHONE_SIGNUP_ENABLED` 后，用户同意协议并通过短信验证即可登录。已绑定手机号进入原账号，未绑定的手机号自动创建账号。
- 本阶段不提供自助换绑或解绑。未来换号必须同时校验原手机号与新手机号；原号码无法接收时走独立账号找回，不能凭新号码验证码覆盖旧号码。短信无法单独解决 SIM 换卡或号码回收风险。

## 安全参数

| 项目 | 当前策略 |
| --- | --- |
| 验证码 | 安全随机 6 位，可含前导零；5 分钟有效 |
| 保存 | HMAC-SHA256 保存验证码与手机号摘要；仅保存手机号脱敏展示值 |
| 用途隔离 | 绑定账号、手机号、用途和随机 challenge；登录码不能绑定账号 |
| 一次性 | 成功验证后消费；重发使旧码失效；并发验证只能成功一次 |
| 错误上限 | 每手机号 15 分钟 5 次，重发不清零；单码最多 5 次 |
| 手机号发送 | 间隔 60 秒；滚动 1 小时 5 次、24 小时 10 次 |
| IP 发送 | 滚动 1 小时 20 次、24 小时 50 次，另有入口登录限流 |
| 全站预算 | 滚动 24 小时默认 200 次，由 `SMS_DAILY_LIMIT` 调整 |
| 持久限流 | 数据库事务和行锁，跨 worker、重启仍有效；网络调用不占用锁 |
| 超时 | 发送超时不自动重试，不返还额度，避免重复发送与收费 |
| 防枚举 | 发送响应不泄露手机号是否注册，验证成功后才告知账号状态 |
| 日志与缓存 | 不记录完整手机号、验证码和供应商异常正文；生产认证响应禁止缓存 |

限额不是人机验证。分布式刷短信仍可能耗尽全站额度造成短信登录暂不可用。上线同时在阿里云设置业务频控、费用预警和预算上限；如果遭遇分布式滥用，再接入验证码挑战，不能通过无限调高配额规避。

## 串号事件的迁移边界

短信只证明手机号归属，无法证明持有器灵会话的人就是旧账户本人。对当前已报告异常的 Cat 用户 `16`，建议在处理归属前配置 `PHONE_BIND_BLOCKED_USER_IDS=16`。这只隔离事件账号，其他账号仍直接短信绑定。

绑定会撤销浏览器会话，但不会撤销已经泄露的 API Key。异常账号的凭证清理、账单核查与 API Key 轮换必须单独处理，不把这次登录迁移当作已完成事件处置。

## 上线配置与步骤

1. 备份数据库和当前代码。安装锁文件中的阿里云官方短信 SDK，先在副本验证新增三张表：`phone_identities`、`phone_challenges`、`phone_auth_guards`。默认 `GENERATE_SCHEMAS=true` 会自动创建；关闭自动建表的部署必须先完成建表再启动新版。
2. 配置 `PHONE_AUTH_SECRET`（一次生成至少 32 字符，建议 `secrets.token_urlsafe(48)`）。安全备份，后续不可直接重置，否则手机号摘要失配，旧绑定无法登录。
3. 配置 `SMS_ACCESS_KEY_ID`、`SMS_ACCESS_KEY_SECRET`、`SMS_SIGN_NAME`、`SMS_TEMPLATE_CODE`、`SMS_CODE_PARAMETER`。使用仅允许 `dysms:SendSms` 的独立 RAM 凭据；不把凭据写入源码或发往前端。
4. 确认模板说明验证码用途与 5 分钟有效期，变量与配置一致。当前前端支持粘贴、数字键盘、系统验证码自动填充；未启用 WebOTP 自动读取，不能承诺所有设备自动填充。若以后启用 WebOTP，应先审核带 `@站点域名 #验证码` 末行的模板。
5. 更新部署中的第三方服务说明，添加阿里云短信处理目的与手机号数据范围。真实签名和模板、运营信息由运营者提供。
6. 先以 `AUTH_PROVIDER=qiling`、`PHONE_AUTH_ENABLED=true` 上线，建议 `QILING_SIGNUP_ENABLED=false`。按需开启 `PHONE_SIGNUP_ENABLED=true`，管理员先绑定并验证手机登录，再通知老用户。
7. 在实际接收人同意下进行一次真实短信发送和登录、绑定验收。当前测试使用模拟投递，不代表实际送达通过。
8. 核查未迁移人数，确定通知与找回安排后切为 `AUTH_PROVIDER=phone`。此时器灵入口和接口关闭；未来自建微信公众号上线后再默认微信入口。

回滚时保留新增表、HMAC 密钥和手机号数据。已绑定用户已禁止器灵登录，不可直接回滚到完全不认识手机号的旧版本，应保留手机认证能力或暂停入口后修复。

## 依据

- [阿里云 SendSms](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms)：模板、签名、计费与非幂等重试约束。
- [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html)：短验证码需要有效期、重放防护与错误次数限制，短信本身不是抗钓鱼凭证。
