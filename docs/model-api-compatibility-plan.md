# Cat API 模型协议统一开发与本地验收计划

下游开发者应能用一个 Cat API 地址和一把平台 Key 找到可用模型，用现成 SDK 提交请求、拿到结果并核对费用。管理员接入一个兼容上游时，地址、凭据和协议配一次，再添加模型映射、能力和价格。同一协议下新增第二个模型应当是一次配置操作。

**首期以视频打通两个方向。** 一个方向是让 New API 把 Cat API 当作上游，经同一个视频接口调用 MiniMax H3 · AutoDL。另一个方向是让 Cat API 把 New API 或其他兼容网关当作上游，让两个新的模型 ID 共用一个视频适配器。文本、视觉理解、图片、音频沿用同一套目录、权限和结算约定，按操作分别验收。首期实现与本地验收结果见第六节。

## 一、先对齐现状与目标

| 原计划容易误判的地方 | 仓库现状 | 本轮要交付什么 |
| --- | --- | --- |
| 上游填地址、Key 和模型名就能用 | 管理配置以单个模型为单位，视频创建与校验还依赖固定的模型类型。旧 `unified_video` 已停用新提交，迁移会把这个协议的配置转成方舟 | 从管理入口添加同一上游的两个陌生模型，验证能保存、启用、调用、下载和结算 |
| 目录列了路径就代表模型支持 | 图片模型当前统一列生成和编辑。视频输入模态使用固定值。部分视觉识别取决于特定模型标识 | 目录逐模型公布已经验证的操作、输入方式和规格。SDK 只读取标准列表字段也能用返回的 `id` 调用 |
| `POST /v1/videos` 就代表 OpenAI Videos 已接通 | Cat 当前只收 JSON，缺省尺寸会提前填成 `720x1280`。AutoDL H3 支持 `480p`、`768p`。旧通用上游适配器发送 Cat 扩展字段，查询成功时强依赖 `metadata.url` | 按目标客户端实际发送的字段、文件编码、状态和取片方式做双向验收 |
| 任务成功就代表对接完成 | Cat 当前对成片返回 307。已有 SDK 测试可跟随跳转读取模拟字节，但目标网关可能拒绝携带凭据的跨域跳转。任务完成与账单入账也可能发生在不同时间 | 从目标网关读到可播放的文件，再按平台回执核对用量、价格快照和实际扣款 |

当前产品说明把 `/v1/videos` 定位为历史兼容入口。本方案将它升级为**经过验收的视频模型的通用入口**。实施时同步更新产品说明、接入指南和接口示例。已有原生路径、旧别名、`nv-ID`、历史任务和账单继续有各自的回归用例。[产品约定](../PRODUCT.md) · [现有公开路由](../api/platform.py) · [目录生成逻辑](../services/platform/model_metadata.py)

## 二、模型、渠道和调用如何对应

| 对谁可见 | 配置或标识 | 用途 |
| --- | --- | --- |
| 下游应用 | Cat API Base URL、Cat Key、公开模型 `id` | 访问目录，按所选操作使用默认路径。标准生成请求把公开 ID 填入 `model`。已有原生入口沿用其模型选择方式 |
| 管理员 | 上游渠道的 Base URL、上游凭据和协议，以及每个模型的上游 ID、公开别名、能力、有效费率和并发 | Cat 将公开 ID 解析到有权访问的模型配置，再用上游 ID 和上游凭据发请求。两个渠道可以提供同名上游模型，但必须能按公开别名确定授权和价格 |
| 调用双方分别保存 | 客户端幂等键、Cat 回执 UUID、上游请求或任务号 | 通用视频响应的 `id` 是 Cat 回执 UUID。其他接口按其响应头 `X-Cat-Request-Id` 取平台回执。平台用已选渠道和上游编号续查。原生透传入口保留供应商原有的任务标识和响应约定 |

**管理员接上游。** 在现有模型配置之上提供「配置渠道 → 拉取模型或手填 ID → 批量选协议和操作 → 设置模型差异、价格和并发 → 启用」流程。支持目录的渠道由 Cat 服务端带上游凭据请求模型列表。仅返回 ID 时由管理员确认能力。没有目录仍可手填。重复导入按渠道和上游 ID 匹配，刷新失败保留已启用配置，别名冲突须提示。连接或目录探测只做读取，生成试单在验收步骤中单独发起。保留已有配置编号、权限与账务关联。[模型配置](../models/config.py) · [管理接口](../api/config.py)

**下游发现模型。** 普通请求 `GET /v1/models` 返回当前 Key 有权访问的公开 ID。显式 `identifier=legacy` 或携带既有工作台能力头时的默认旧 ID 行为继续覆盖。目录保留 `object/data/id` 以及 Cat 的 `kinds`、输入输出模态、`endpoints`、`pricing` 等扩展。按操作描述 JSON、文件、流式或异步支持，同一份有效能力同时用于目录、服务端校验和示例。对于文本扩展参数，保留现有显式透传规则。[目录与权限回归](../test/test_public_model_metadata.py) · [Key 策略回归](../test/test_api_key_policy.py)

| 目录用途 | 下游操作与当前边界 | 每类的验收样本 |
| --- | --- | --- |
| 文本 | `/v1/chat/completions`、`/v1/responses` 按已验证操作列出。当前按入站路径调用同名上游操作，`text_api` 用于标注推荐入口 | 对各入口各测一次 JSON 和 SSE，核对工具调用或扩展字段、终态、实际用量和回执 |
| 视觉理解 | 与文本共用对话入口，按可确认的图像或视频输入模态展示。同一公开 ID 可以出现于两个用途 | 上传一张已知内容的测试图，走公布的输入格式，检查实际出站图像字段和文本结果。宣称视频输入时另测视频 |
| 图片 | `/v1/images/generations` 和 `/v1/images/edits` 分别声明。OpenAI 兼容文件编辑、URL 编辑、方舟和 OpenRouter 按各自实际通道处理 | 分别验纯文生成、URL 编辑、受支持渠道的文件编辑。核对输出 URL 或声明支持的 Base64、实际产图数和计费档位 |
| 视频 | 本期通用协议覆盖创建、查状态、取成片。画质增强在视频类中单列为处理操作，保留 MediaKit 原生路径 | 对通用视频执行下文两个方向的整链路。增强用原生任务回归 |
| 音频 | 现有 MiMo 音色设计经 Chat 返回 WAV，SeedASR 经原生提交和查询。通用语音合成、文件转写各自立项 | 验 WAV 实际时长与费用、SeedASR 原任务查询和识别结果。未来若提供 OpenAI 同步文件转写，须先与现有同路径的异步 JSON 提案区分契约，再公布入口。[媒体任务提案](platform-media-contract.md) |

## 三、视频首期开发顺序

### 1. 固定两个互通方向和客户端版本

| 联调方向 | 本地拓扑与配置 | 判定依据 |
| --- | --- | --- |
| New API 调 Cat | 调用方 → 固定版本 New API → Cat 公开模型 → 模拟 AutoDL。New API 渠道使用 Cat Key，核对模型映射后抵达 Cat 的公开别名 | 通过 New API 提交、查询并下载，检查文件字节。记录模型名是否需要映射、谁补了默认参数，并将 Cat 回执关联到该次调用 |
| Cat 调 New API | OpenAI SDK → Cat → 固定版本 New API → 测试供应商。Cat 后台配置 New API 的地址和独立测试 Key。另外用可记录请求的兼容上游挂两个陌生模型，验证配置复用 | SDK 只改公开模型 ID 即可切换。断言上游收到对应的模型名、路径和参数，两笔任务分别能取成片、查回执 |
| 独立对照 | 同一 SDK 直连 Cat，经 H3 原生适配器运行纯文、URL 单图和文件单图样本 | 检查 SDK 发出的实际请求、Cat 发给工作流的参数、结果和计费，用来定位每一跳的差异 |

本地 SDK 以仓库锁定的 OpenAI Python `2.17.0` 为基线。New API 首选可复现样板 `v1.0.0-rc.51`、Sora 任务插件 `1.1.0`。该插件自行在渠道地址后拼 `/v1/videos`，且默认声明的模型是 `sora-2` 和 `sora-2-pro`。SDK 的 Cat Base URL 填到 `/v1`，该插件的渠道地址则填到站点根。MiniMax H3 的实际模型绑定、分组、价格和两端收到的 ID 必须留样。仅在目标实例确实支持时，才将该组合标为兼容。换版本时重新记录镜像或提交与插件版本。[SDK 依赖锁](../uv.lock) · [New API 固定版本的渠道实现](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.51/plugins/tasks/sora/plugin.js) · [New API 对外 HTTP 调用说明](https://github.com/QuantumNous/new-api-docs-v1/blob/main/content/docs/en/plugins/usage.mdx#openai-video-compatible-interface)

### 2. 在 Cat 入站统一字段、默认值和素材

- 标准创建保留 `model`、`prompt`、`seconds`、`size`。带单图文件时接收 `multipart/form-data` 的 `input_reference`。已发布的 JSON HTTPS `input_reference`、`references`、`duration`、`resolution` 和 `aspect_ratio` 继续可用。两套字段同时出现且冲突时，在调用上游前返回字段错误。
- 解析时保留哪些字段由调用方显式给出，选定模型后再补默认。H3 样板只传模型与提示词时，以 4 秒、已配置有效费率的默认 `768p`、`16:9` 验证。模拟工作流应收到 `duration=4`、`resolution=768p横`。用户显式传 `720p` 或默认档缺价均返回错误。公开的 `size` 用经验证的像素对映射到档位和方向，并能原样回填请求。特别覆盖宽高需取整的 768p 横屏。其他已发布渠道的缺省行为逐个回归。
- 对 H3 拒绝参考视频和首尾帧。参考图数量、格式、音频及可选开关按该工作流实际使用的字段声明。保留现有 H3 渠道素材限额。multipart 仅在指定入口放行，先鉴权，再限文件数和实际读取字节、验证图片格式，并将有效文件写入当前账户的限时对象。模拟上游要真正读到相同内容。测试超限、损坏、存储失败及过期清理。[请求校验](../services/platform/request_data.py) · [视频能力](../services/video/capabilities.py) · [AutoDL 工作流](../services/video/autodl.py)

### 3. 打通通用上游、任务查询与下载

使用独立的新协议标识接通管理配置校验、视频工厂和上游适配器。复用现有提交、轮询和结算流程，解除通用协议对固定供应商模型枚举的依赖。保留旧 `unified_video` 到方舟的迁移及迁移前任务的原地址查询。对同一登记协议，后台可一次选择多个上游模型，按模型覆盖真实规格。验收必须经过正常管理入口并在重启后再次读取配置。[工厂](../services/video/factory.py) · [旧通用适配器](../services/video/unified.py) · [迁移逻辑](../services/video/ark_migration.py)

| 环节 | 实现与验收要求 |
| --- | --- |
| 出站创建 | 按上游已验证的路径、凭据和编码发送上游模型 ID、提示词及有效规格。通用上游使用其支持的 `seconds/size`、单图文件或 URL。AutoDL 生成自己的工作流字段。不得把 Cat 专用扩展无条件透传给通用上游 |
| 查询 | 保存 Cat 回执、受理时的路由及上游任务号，GET 继续查原任务。对外维持 `id/object/model/status/progress` 等现有字段。按协议把已知状态映射到 `queued/in_progress/completed/failed`，保留可诊断的错误。未知状态、格式异常和缺成片有界重查，仍不确定则进入待核对 |
| 取成片 | 上游可能在完成时返回可读 URL，也可能只给任务号，要求携带上游 Key 访问 `/content`。后一种由 Cat 服务端按原渠道鉴权取片。下游只访问自己的任务。原先可用的 `metadata.url` 保持兼容，受保护的成片可指向平台可访问的下载入口 |
| 下载兼容 | 目标 New API 的插件会带凭据请求内容，该版本的下载代理会拒绝带凭据的跨域重定向。新通用任务的默认 `/content` 应在 Cat 同源完成鉴权并流式返回视频，GET 能取到可播放的字节，HEAD 无正文且媒体类型正确，未完成沿用 409。历史任务保留原 307 行为。由服务端取片时校验目标和重定向地址，凭据只发给所属渠道。以不同源的测试存储核对实际收到的请求头。下载或刷新均不触发生成。[固定版本下载代理](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.51/controller/video_proxy.go) |

### 4. 让一次受理对应一次可核对的结算

| 情况 | 调用方行为与平台保证 |
| --- | --- |
| 准入或参数错误 | 鉴权、模型权限、有效规格与费率、余额、并发都在付费提交前检查。验证无效 Key 401、越权 403、余额不足 402、并发已满 429 及 `Retry-After`。这些请求的上游提交数和扣费数均为 0 |
| 重复提交 | 请求抵达 Cat 后，同账户、同 `Idempotency-Key`、同视频请求返回原任务。异体返回 409 和原回执编号。文件请求用业务字段和文件内容摘要判同，避免临时签名 URL 或表单边界改变摘要。并发重放与历史 JSON 重放分别测试 |
| 断线或重启 | 已知上游任务号就续查。提交后读超时、成功回包缺任务号或受理结果不明时，保存回执并标记 `review`。用原请求标识向支持回查的上游核对。上游无法回查时留待核对，禁止自动重发付费 POST 或切换渠道补发。覆盖 AutoDL 将不确定异常误当作明确拒绝的现有分支 |
| 客户端恢复 | 任意合法原幂等键用 `GET /v1/requests?request_key=…` 取回 Cat UUID，再查 `/v1/videos/{id}` 或 `/v1/requests/{id}`。旧 `/v1/videos/req-{UUID}` 继续覆盖 UUID 键。查询、下载、重放同时校验账户和 Key 的模型权限。改价、停用或改路由后的旧任务按受理记录恢复 |
| 成片与费用 | 已有成片可以先返回。按受理时的价格快照、折扣和可确认用量结算，记录用量来源。AutoDL 的运行耗时不能当成片秒数。固定时长订单可沿用订单秒数。未确认用量进入 `review`，已测量但尚未扣款的记录可重试结算。对账用回执的 `settlement.status/amount` 和实际流水。旧视频对象可能将待核对显示成 `failed`，客户端需结合 `billing_status` 与回执判断 |

本地账务算例使用 4 秒、0.20 元/秒、折扣 1、无付费输入，预期扣款 0.800000 元。并行轮询、服务重启、重复下载及结算重试后，应查到同一任务、一次上游创建、一笔扣款。明确拒绝为 `not_charged`，不确定为 `review`，已入账为 `settled`。按平台回执可关联模型配置、上游编号、阶段、耗时和错误类别。日志和验收记录隐藏密钥、签名参数及文件正文。[受理与结算](../services/platform/calls.py) · [视频任务](../services/platform/videos.py) · [回执](../services/platform/receipts.py)

经过另一层网关时，分别捕获每一跳的幂等键、任务映射和自动重试次数。上游已受理但响应丢失时，从最初的客户端重试，并核对供应商实际收到了几次 POST。只有稳定传递或映射了同一业务标识且实测只创建一次，才可声明该组合支持端到端重试。中间网关丢键时，记录限制。有原任务号就查原任务，无编号且无法回查时将本次调用留待核对。

## 四、从视频样板推广到全目录

为每个操作保存一组可复用的样本，涵盖下游原始请求、实际出站请求、供应商响应、下游可读结果、对应回执和金额。通用客户端与上游遵循同一协议时，保留协议原有字段和返回形式。需要原生转换时，适配器负责翻译这一跳。鉴权、模型选择、并发和结算沿用平台已有流程。

错误样本同时覆盖平台拒绝、上游 HTTP 错误、HTTP 200 携带业务错误，以及流式输出中断。每例检查客户端能读取的错误、可公开的请求编号和回执状态。已透传的原生错误保留状态码与可安全公开的内容，不能把业务失败记作成功扣费。

1. **文本与视觉理解。** 先选一个 Chat 上游和一个 Responses 上游，在相应通用配置下各接第二个模型。目录按操作与输入模态选择，验证 SSE、工具与图像输入能到达正确上游。发布经过双向验证的操作组合。
2. **图片。** 先跑通一个 OpenAI 兼容上游的生成与文件编辑，再用一个只接收 URL 的渠道验同一客户端入口。目录写清哪个模型接受哪种输入。逐单核对返回的图片、张数与收费方式。新增同协议模型通过配置加入。
3. **音频与媒体处理。** 现有音色设计、ASR 和增强先保留可调用的原生能力。有匹配的通用上游时，为语音合成和文件转写分别定义输入、输出和可计量单位，各用真实客户端对接一个上游样板。长音频异步任务按独立任务契约推进。每项通过后再加入公共目录。

## 六、2026-11-20 本地实施与验收记录

工作区以 Cat 提交 `1fdcc37` 为基线。SDK 为 OpenAI Python `2.17.0`。网关使用 `calciumion/new-api:v1.0.0-rc.51`，镜像摘要为 `sha256:d6effcdbc58175494765c0cc5954bdacb2300516eec79ba1a9c61f9b9fae7b49`，在隔离实例安装该标签自带的 Sora 插件。Cat 与 New API 各使用自己的测试账户、Key 和本地数据库。

| 验收 | 实际配置与结果 |
| --- | --- |
| New API → Cat → 模拟 AutoDL | New API 渠道绑定 Sora 插件，对外模型 `sora-2` 映射到 Cat 公开名 `minimax-h3`。渠道地址填 Cat 站点根地址。纯文、URL 单图和文件单图均经 New API 完成并下载。工作流收到 4 秒和 `768p横` |
