# 在途生成请求的停机保护

## 适用范围

模型请求期限为 600 秒，外层进程管理器和应用收尾的等待预算必须与之匹配。短等待后强杀进程会截断仍在正常执行的响应；固定 15 秒取消后台流也无法保护合法的长请求。

本次仅添加发布排空、按原请求期限等待后台文本流、现有启动入口的优雅退出参数和回归测试。不改 Key 认证、用户权限、价格、结算规则、CI 或依赖；不重提历史请求，不恢复缺失的历史正文。

## 代码行为

- 在统一 `admit()` 入口检查排空标记，数据库等待后再检查一次，覆盖文本、图片、视频和原生协议生成。被拒绝的新工作返回 HTTP 503 与 `Retry-After: 30`，不创建受理回执、不调用供应商、不产生计费。
- 已受理工作继续执行。视频查询、调用回执、账户读取以及 `/health` 存活检查不受此开关影响。
- `/api/health/ready` 在排空时返回真实 HTTP 503，非排空时检查数据库并返回 200。该路径可走现有 `/api/*` 代理。它表示是否接收新生成，**不表示所有在途请求已经完成**。
- 后台流按照创建时保存的单调时钟 deadline 等待，另留 30 秒收尾；原有 600 秒请求期限不因停机重新计时。超出收尾期限才断开输出队列、取消任务，并最多再等 30 秒清理。此函数的等待有界；清理仍卡住会记录错误，整个进程的最终退出仍受外层管理器预算约束。
- 客户端断开不取消已提交的供应商流。会继续收集结果与用量，沿用现有一次性结算逻辑。
- 主生命周期在关闭数据库与结算 worker 前等待文本流收尾。

## 运维排空开关

配置 `DEPLOYMENT_DRAIN_FILE`。默认 `data/deployment-draining` 相对于项目根目录，已被 `data/` 的 Git 忽略规则覆盖。跨 release 目录部署必须使用同一个、服务进程可读、运维用户可写的绝对共享路径。

```sh
python scripts/drain.py begin
python scripts/drain.py status
python scripts/drain.py end
```

开关保留到明确执行 `end`，进程重启不会自动解除。脚本只操作自己的标记，不覆盖或删除其他内容。标记不含凭据，不新增 HTTP 管理接口，不变更认证权限。

正常发布顺序：

1. 按项目规则测试、提交、推送 GitHub，服务器将指定提交拉取到独立的干净 release 目录；不要在仍处理请求的旧进程目录里提前覆盖代码。
2. 确认新旧进程使用相同 drain 路径，外层管理器等待预算已经批准并生效。备份必要配置与数据库。
3. 在旧版本执行 `begin`，确认新生成返回 503、已有查询仍可用。
4. 向旧进程发送 TERM，等待正常退出。不要因为部署脚本自身超时而追加 `kill -9`；若出现强杀或清理超时，判定发布检查失败并排查。
5. 启动已拉取的新提交。保持 drain 标记，先检查存活、版本和必要只读接口，再执行 `end`，确认 readiness 为 200、生成恢复受理。

## 需按部署环境审核的进程管理配置

使用 Supervisor 时，应将不含密钥的通用启动配置纳入版本管理，部署专用信息留在被 Git 忽略的配置中。审核后采用以下等待预算，保留原 command 的其他环境和参数：

```ini
# command 原有 uvicorn 参数末尾增加：
# --timeout-graceful-shutdown 660
stopsignal=TERM
stopwaitsecs=1350
```

预算：HTTP 优雅退出最多 660 秒；后台流剩余模型期限最多 600 秒，加两阶段清理共 60 秒；额外留 30 秒外层裕量。因此外层至少覆盖 1350 秒。常规退出会在任务结束后立即完成，不固定等待 22.5 分钟。发布工具、SSH 包装器或其他上级管理器也不能提前强杀进程。

仓库现有 `scripts/dev.sh` 与 Dockerfile 已显式加入 Uvicorn 的 660 秒参数。但 **Dockerfile 无法配置 Docker 的 stop 等待时长**：容器部署还需人工审核运行配置中的 `stop_grace_period: 1350s`，或使用 `docker stop --time 1350`，不能沿用默认短等待。

### 第一次部署的额外阻碍

如果运行中的旧版尚不认识 drain 标记，新代码不能保护它自己的首次替换。必须先通过经过审核的维护入口暂停新生成，并确认在途请求完成；同时先落实外层停止预算，再停止旧版。没有完成这一步，不允许直接重启旧版“试一下”。

如果部署目录与 Git 存在版本偏差，必须先核对并将应保留的修改纳入正常 Git 交付，不能强制覆盖未知差异。

## 测试与限制

- 回归用例包含 15.2 秒慢流，检查原响应完整结束、供应商只执行一次、只计费一次；另覆盖原 deadline 超时、客户端断开、输出队列堵塞和排空前后读取。
- 本地 Uvicorn 子进程测试在收到首段后开启排空，确认第二个生成被拒绝；发送 SIGTERM 后检查原连接收到尾段及 `[DONE]`，且进程完成正常收尾。使用隔离 SQLite、模拟供应商及临时文件。
- 运行测试：`python -m pytest test/test_graceful_drain.py -o addopts='' -q`。这不能替代实际 Supervisor/Docker 环境的停止预算验收。
- SIGKILL、断电和宿主崩溃无法靠进程内等待保证恢复；本功能不新增正文持久化或自动重试收费生成。

参考：[Supervisor stopwaitsecs](https://supervisord.org/configuration.html)、[Uvicorn graceful shutdown](https://uvicorn.dev/settings/)。
